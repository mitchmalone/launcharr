## Breaking changes

- none. One permission note: the **launcharr loupe** for `colorpicker` (opt-in, Settings →
  General → "Use the launcharr loupe") asks for Screen Recording once when you turn it on;
  off — the default — it's Apple's `NSColorSampler` and nothing prompts.

## Highlights

**Multi-display.** The bar sits on **every** screen, and the launcher opens on the screen
your mouse is on. Both were meant to work before and both quietly collapsed to the primary
display (Tauri's monitor API is empty for an accessory app, and its cursor→monitor lookup
never matches on Retina) — launcharr now asks CoreGraphics directly. Bars follow displays
as they come and go, the notch layout follows the window if it lands on the built-in
panel, and hover cards open on the bar you're actually pointing at.

**Agents, observed not reported.** Agent cells disappear when the agent does: dead tmux
panes and dead processes are reaped, `⌫` in `agents ⏎` dismisses one by hand, and
**herdr** joins tmux as a second multiplexer — every agent herdr detects gets a cell,
click to jump.

**`colorpicker`** with an optional 2–8× loupe (framebuffer capture, so every app shows —
including the ones that hide from screenshots), `#RRGGBB` straight to the pasteboard,
confirmed by a **toast** row. **`lorem`** is a built-in now (five volumes, `lorem ⏎` picks).

**`?` mode as turns:** first question pinned in the header, transcript below, follow-up
prompt at the bottom, Claude-style thinking spinner.

**Bar + desktop:** wifi cell hovers a card (SSID, IP, router, DNS — click → Wi-Fi
settings), battery card breathes, AeroSpace `gaps` now means the _visible_ gap (borders
and the showing bar are factored in), unfocused border reads as an edge. Settings →
Agents splits into three sub-tabs; About fleshed out.

## Performance receipts

Measured on the release build, 2026-08-19 (M-series, two displays, bar on, agents
monitor on):

| Metric                         | Budget   | This release |
| ------------------------------ | -------- | ------------ |
| Hotkey → panel visible         | < 100 ms | 2.6 ms       |
| Cold start → hotkey registered | < 1 s    | 202 ms       |
| Idle memory (panel hidden)     | < 120 MB | 109 MB       |

Idle memory is the number to watch: every display costs a bar, and a bar is a WebKit
view. Two bars up here and still under 0.4.0's single-bar reading — the shared WebKit
pool amortises the second view. Bar off ≈ 0.3.1.
