# v0.4 — desktop layer

## Goal

`brew install mitchmalone/tap/launcharr` gives a fresh Mac working tiling that looks like
Mitch's setup, without the user ever seeing an `aerospace.toml`. Window borders
(JankyBorders) and a system window-corner-radius knob are one toggle away in Settings.
Mitch's own machine runs the launcharr-managed versions from this release on — the
hand-installed AeroSpace + borders come off first.

## In English

Install launcharr → AeroSpace comes with it, preconfigured. Settings → **Desktop** shows a
handful of knobs: modifier key, gaps, workspace count, which apps float; a **Window
borders** row that is an "Install via Homebrew" button until `borders` exists, then a
toggle + width; and a **Window corners** slider (system radius, 1–26, "system" resets).
Change a knob → launcharr rewrites the AeroSpace config and reloads it live. Flip
`managed` off → launcharr leaves the file alone; you're back to text editing. Already ran
your own AeroSpace? First launch asks: keep yours, or take launcharr's (with a backup).

## Context

- Today: AeroSpace + borders + aerospace-swipe are hand-installed via Homebrew;
  `~/.config/aerospace/aerospace.toml` (a copy) and `~/.config/borders` (symlink) point at
  dotfiles. `exec-on-workspace-change` already touches `~/.config/launcharr/triggers/`;
  the bar's workspace cell shells `aerospace list-workspaces` (`bar.rs`).
- Licences (verified 2026-08-17): AeroSpace MIT, JankyBorders **GPL-3.0**, launcharr MIT.
  Homebrew-dependency + spawn-as-process triggers no GPL obligation; vendoring the binary
  or porting its code would. Hence: nothing vendored, ever.
- Corner radius: `defaults write -g NSConvolutionOverride1 -float N` (hidden AppKit
  global, no SIP). Verified on 27.0 `26A5406e`: TextEdit honours it after relaunch;
  **`0` reads as unset — minimum is 1**; Finder unchanged after `killall Finder` (needs
  logout, or exempt); Quick Look ignores it. Undocumented → fail-visible, "may stop
  working on a future macOS" in the UI.
- CornerFix (makalin) and macos-corner-fix (m4rkw): dylib injection / SIP off. Rejected.
- Cask: CI (`release.yml`) `sed`s version + sha into `Casks/launcharr.rb` in the tap;
  structural lines (`depends_on`) are edited in the tap once, by hand — CI leaves them.

## Approach

**Install.** Cask gains `depends_on cask: "nikitabobko/tap/aerospace"`. borders is _not_
a cask dep — it's opt-in, installed on demand from Settings (`brew install felixkratz/formulae/borders`),
because it's GPL and because most users won't want it. Zip users: launcharr's first-run
detects a missing `aerospace` and offers the same one-click `brew install` (or shows the
command when Homebrew is absent). No downloads by launcharr itself — zero-network holds.

**Config.** New `config.json` sections, mirrored TS ↔ Rust:

```jsonc
"desktop": {
  "tiling":  { "enabled": true, "managed": true, "modifier": "alt", "gaps": 8,
               "workspaces": 6, "float": ["com.apple.systempreferences", "com.raycast.macos"] },
  "borders": { "enabled": false, "width": 5, "style": "round" },   // colours from theme
  "cornerRadius": null                                              // null = system
}
```

`renderAerospaceToml(desktop, theme)` and `bordersArgs(desktop, theme)` are pure functions
in `packages/core` (tests first; the template is today's dotfiles toml minus sketchybar /
personal bits, with a `# generated by launcharr — edit ~/.config/launcharr/config.json,
or set desktop.tiling.managed=false` header). Rust writes the file, runs
`aerospace reload-config`, and (re)spawns `borders` with flags — no `bordersrc`. Border
colours = theme `accent` (active) / `dim` (inactive), so themes retint borders.

**Escape hatch = migration.** `managed: false` → launcharr never writes the file. First
launch with an existing unmanaged `aerospace.toml`: adopt (backup to `aerospace.toml.bak-
launcharr`, overwrite) or leave (`managed: false`). AeroSpace keeps its own LaunchAgent /
`start-at-login`; launcharr only reloads it. borders is launcharr-supervised (start on
enable, restart on theme change / crash, stop on disable; never uninstalls). Tiling
toggleable like launcher/bar; disabling stops borders and un-manages, never deletes.

**Rust surface** (thin, boring — DECISIONS entry): `desktop_status` (aerospace/borders/
brew presence + versions + managed state), `desktop_apply` (write toml + reload + borders
respawn), `desktop_install(dep)` (spawns `brew install`, streams progress via event),
`desktop_corner_radius(set|clear)` (`defaults write/delete -g NSConvolutionOverride1`).
Modules: `deps.rs` (detect/install), `tiling.rs` (render+reload+borders supervision).

## Acceptance criteria

- [ ] Fresh Mac (or a clean user account): `brew install …/launcharr` → tiling works with
      the launcharr layout, no `aerospace.toml` ever opened.
- [ ] Settings → Desktop: gap change is visible within one `reload-config`; modifier
      change rebinds; borders row installs → toggles → retints on theme switch; corner
      radius slider changes TextEdit on relaunch, "system" restores.
- [ ] `managed: false` → launcharr stops writing; hand edits survive restarts.
- [ ] Existing-install first launch: adopt backs up + overwrites; leave sets managed=false.
- [ ] Mitch's machine runs only the managed AeroSpace/borders; `brew list` shows aerospace
      as launcharr's dependency, borders installed via the Settings button.
- [ ] `pnpm verify` green; core renderer tests exhaustive; budgets untouched (nothing on
      summon/match/launch paths).

- [ ] Theme switch retints borders without flicker worth noting.
- [ ] Corner radius: TextEdit relaunch honours; note Finder/logout behaviour in JOURNAL.

## Out of scope

- aerospace-swipe (personal; decide separately whether launcharr wants gestures).
- Per-app border colours, per-app corner radius, anything CornerFix-shaped.
- Vendoring or porting AeroSpace/borders code. Sketchybar of any kind.
- Settings migration off the native window (P1) — Desktop tab lands in the native window
  and moves with the rest.

## Risks / open questions

- `NSConvolutionOverride1` is undocumented; may vanish. UI says so; setting is fail-visible.
- `brew install` from a GUI app: PATH/env (`HOMEBREW_NO_AUTO_UPDATE=1`, non-TTY), Rosetta
  Macs (`/usr/local`), and Homebrew absent (show the command). Streaming stderr is enough.
- Cask depending on a third-party tap cask: Homebrew supports `depends_on cask:` with a
  fully-qualified name; verify `brew install` auto-taps `nikitabobko/tap` (it should —
  `depends_on cask` triggers the tap). Fallback: document `brew tap` first.
- AeroSpace beta vs stable channel: pin the stable cask; note the min version we render for
  (`config-version = 2`).
- Bar workspace cell during the uninstall window on Mitch's machine: expected blank.
