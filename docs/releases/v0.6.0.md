<!-- v0.6.0 — widgets: the bar becomes a platform -->

## Breaking changes

- none. One reference-widget note: `github-actions.ts` no longer reads a JSON feed
  (`GITHUB_ACTIONS_FEED_URL`) — it talks to the GitHub API with your GitHub CLI login.
  If you'd pointed it at a custom feed, keep your old copy; the widgets dir is yours.

## Highlights

**Widgets: drop a TypeScript file in `~/.config/launcharr/widgets/`, own a cell in the
bar.** A widget answers `manifest` and `tick` with JSON — launcharr runs it on its own
cadence (Bun or Node found automatically; any executable in any language works), renders
the cell and its hover card in the theme, on every display, and never lets it near the
hot path. Live dir watch: drop it in, it's there; edit it, it re-ticks; `touch
~/.config/launcharr/triggers/widget.<id>` to tick on demand. Fail-visible: a broken tick
keeps the last good view, turns the cell red, and puts the reason in the card. Reference
set ships in the repo — uptime, GitHub Actions, Vercel deployments, TRMNL — and the
contract is documented in `docs/WIDGETS.md`.

**Credentials that mostly just work.** Widgets piggyback the CLIs you're already signed
in to — `gh auth token`, the Vercel CLI's login — so GitHub Actions lights up with zero
setup. When a credential is missing or goes stale the cell dims (nothing broke, nothing
red) and the card, and Settings, name the problem with the fix as a copyable command
(`gh auth login`, `vercel whoami`). Prefer your own token? Every credentialed widget
takes one in Settings → Menubar → Custom widgets, stored in the **macOS Keychain** —
never in config.json, never shown back. Settings stay quiet: a healthy widget is one
line; the fields appear only when it needs you.

**Settings grows widget management.** Menubar splits into **Layout / Custom widgets**:
place widget cells on the zone board like built-ins, and install from a URL or a file,
tick, remove, open the folder — with each widget's health ("ok · 2m ago", or why not)
inline. General splits into **General / Color picker / Config** sub-tabs, and the
settings window now actually comes to the front when summoned from the panel.

**One colour language.** Every strip colour is a theme token now — a new `warn` token
joins the palette, and the rule is simple: **fine is `fg`**. A done agent, a healthy
battery, an `ok` widget all read as plain foreground; accent means busy, warn/danger
mean it needs you — and all of it retints with your theme. Wifi arcs keep their
footprint at every strength (lost arcs ghost instead of vanishing), and the battery and
wifi glyphs are optically sized so nothing in the strip reads squat.

**The quiet strip.** Wifi, battery, and awake cells are glyph-only now — strength arcs,
a battery tier judged against your macOS charge limit (80 % on a limited pack reads as
full), a coffee cup that lights while a hold is armed — with the words (SSID, exact %,
elapsed/remaining) in the hover card where they belong. **Awake holds survive a
relaunch**: an armed hold is persisted and re-armed at launch under the same rules, with
a toast to say so. Agent cells got smarter too: Claude's background daemon no longer
claims a cell, and running subagents ride the parent — a count on the cell, the list in
the hover.

**TypeScript everywhere.** Bundled scripts and reference widgets are `.ts` — no shebang,
no chmod, no build: launcharr finds your Bun (or Node) and runs them, even from a
Finder-launched app with its bare PATH. The Python bundle is retired (`.py.retired`,
edits preserved).

## Performance receipts

Measured on the release build, 2026-08-20 (M-series, two displays, bar on, agents
monitor on, four widgets ticking):

| Metric                         | Budget   | This release |
| ------------------------------ | -------- | ------------ |
| Hotkey → panel visible         | < 100 ms | 2.0 ms       |
| Cold start → hotkey registered | < 1 s    | 186 ms       |
| Idle memory (panel hidden)     | < 120 MB | 118 MB       |

Idle memory carries two bars **and** the widget scheduler; widgets are child processes,
resident for milliseconds per tick, so the number moves with displays, not with how many
widgets you install.
